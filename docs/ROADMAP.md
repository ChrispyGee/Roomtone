## Known limits (by design, for now)

- S1 and S2 can't truly group; *play along* is the stand-in.
- **Setting up a new speaker isn't possible from Roomtone.** A speaker that has never been set up belongs to no system (it shows *Not set up yet*). Adding it to a system needs the maker's own set-up channel, which requires the maker's certificates and a signed handshake, and registering a speaker with an account goes through the maker's cloud. Roomtone has neither, so set a new speaker up once with the Sonos app; Roomtone controls it from then on. (The speakers' open control interface has no way to create or join a system, and its `EnterConfigMode` action refuses requests on a Play:3, checked read-only on 2026-11-18.)
- Apple Music, YouTube Music and SoundCloud only play saved favorites (the providers block third-party sign-in).
- *Play along* links aren't saved between runs.
- "Automatic" language on Windows reads only environment variables.
- Translations need native-speaker review (de, fr, es, it, nl).
- The details under a restore summary (why something couldn't be restored) are in English only.
- Importing an M3U, PLS, XSPF or CSV matches songs only to your music folders (Music Library › Add folder); songs from streaming services can't be brought across from other apps' lists.

## Ideas

Roughly in order of value. Discuss in an issue before starting the big ones.

1. **Signed packaging (mostly done, 2026-11-24)**: the macOS `.dmg` is signed with a Developer ID and notarised by CI (from 0.9.6). Windows is covered by the **Microsoft Store** (certified, signed by Microsoft); the installer on GitHub stays unsigned because SignPath Foundation declined (the project isn't established enough yet). Revisit a paid route (Azure Artifact Signing or a commercial certificate) or re-apply to SignPath if adoption grows; see [SIGNING.md](SIGNING.md). Linux `.deb`/`.rpm` are unsigned (checksums and build attestations ship with each release). An Intel Mac build and Linux AppImage/Flatpak remain possible.
2. **Backup follow-ups**: bring a streaming-service favorite across when the account number differs, restore onto chosen systems (shipped after 0.9.6, demo only) and try it on real S1 and S2 speakers (it's only tested on a pretend system and the demo so far). (Playlists as M3U, PLS, XSPF and CSV, and `roomtone backup` / the `save_backup` assistant tool, shipped in 0.6.1; command-line restore stays out until restore is proven.) Keeping favorites in step between systems is item 29.
3. **Phone-friendly web remote**: serve a small responsive page from the headless HTTP server (protected by the access key), so any phone, tablet or computer can control Roomtone without an app. Drives the same commands as the window and the assistant link. **Design proposal written, not yet agreed: [WEB_REMOTE_DESIGN.md](WEB_REMOTE_DESIGN.md)** (separate switch and port, pairing by QR code and session cookie, per-device roles, hardening first).
4. **Menu-bar or tray mini player**: **the Mac menu shipped in 0.9.4** (*Settings › Appearance › Show in the menu bar*; Mac only; **the maintainer tried it on a Mac and said the menu works, 2026-11-22**; also covered by unit tests): what's playing, play/pause, next, previous, volume, the room list, *Pause all rooms*, *Open Roomtone* and *Quit*, and closing the window keeps Roomtone running there. The **room name next to the icon** shipped in 0.9.5 (experimental; **the maintainer tried it on real speakers, 2026-11-23**). **The Windows notification-area icon shipped in 0.9.5 too (experimental; tried on a Windows 11 virtual machine, 2026-11-23).** **The small pop-up player is built (after 0.9.5, experimental, *Open a small player when the icon is clicked*; shown on the demo system only).** **The same pop-up player on Windows is built (experimental; not yet tried on a Windows PC).** Still open: a Linux tray (item 26; needs a tray library). (The remembered window size shipped in 0.6.0.)
5. **More streaming services, and more for the favorites-only ones**: add services beyond Spotify, Amazon Music, Deezer, TIDAL and Qobuz, and find legitimate ways to do more than play saved favorites with Apple Music, YouTube Music and SoundCloud (browsing and search where a service allows it). Open question: which services let a third-party controller sign in at all.
6. **Package managers**: the Homebrew tap (`ChrispyGee/homebrew-roomtone`) is live for 0.6.1; the winget manifest and Arch `PKGBUILD` are made for each release (see `docs/RELEASING.md`) but not published yet (a winget-pkgs pull request, the AUR package). The Homebrew install was tried for real (macOS, 0.6.1); winget and Arch haven't been. Flathub is separate. The main Homebrew cask list waits for signing.
7. **Gentler alarms**: snooze, duplicating an alarm, alarms in several rooms at once and one-off timers per room are done (the last three in 0.9.3, tested on the demo system and with tests, **not yet on real speakers**: in particular whether a one-time alarm is left behind after it rings, which Roomtone tidies away five minutes later). A **longer fade-in** (1 to 30 minutes) is built too, **not yet tried on a real speaker**: Roomtone saves the alarm quiet and raises the volume step by step, so it only works while Roomtone is running (otherwise the alarm stays quiet). Still open: a fade the speaker does by itself, which the speakers don't offer.
8. **Lyrics (shipped in 0.8.0 as an experiment)**: an off-by-default switch that shows lyrics from lrclib.net on Now Playing. It works well with real songs; it stays experimental until it has had more use, and will be removed if it doesn't earn its place.
   - **Looked at in 0.8.1: other lyrics sources, to use instead of or as a fallback after LRCLIB.** Questions to answer for each: does it need an account or key (we ship none, so a key would have to be the person's own), what do its terms allow (showing words in an app, caching, attribution), does it carry time-stamped lines, how good is its coverage of the songs people play here (try the same set of songs on each), does it work without sending more than title, artist, album and length, and how does it behave when it's down. First look (2026-11-17, from public pages only; nothing tried yet): **Musixmatch** has an official API, but its free plan reportedly returns only about 30% of each song's words, needs a personal key and is for non-commercial use, so full words need a paid licence (verify at developer.musixmatch.com/plans); unofficial access is against their terms. **LyricFind** is commercial licensing only. **Genius**'s API gives song details and links, not the words. **lyrics.ovh** is free and keyless but plain text only, has had no code changes since 2022 and looked slow and unreliable in a 2026 directory test. **NetEase** and similar services are unofficial, with no terms found. Tools that scrape several sites (such as YouLy+ or SyncLyrics) are out. **LRCLIB itself** needs no account, asks clients to send an identifying User-Agent (we do), and allows about 90 requests a minute per address, with an optional free app id for more; it answers `429` with `Retry-After`, which we don't yet honour and should. **0.8.1 did the small part**: it honours `429` and `Retry-After` and retries a failed song next time it plays. LRCLIB stays the only source; a second one (for example the person's own Musixmatch key) waits until its terms are confirmed to allow showing the words. Whatever is added is listed in SPEC.md §9, stays off by default, and falls back in a fixed, documented order.
9. **Saved play-along links**, and play along for more than two systems.
10. **More languages**: see "Adding a language" in [CONTRIBUTING.md](../CONTRIBUTING.md).
11. **Home-theatre settings and stereo pairs**: surround and sub levels, where the speakers allow it locally. Also *creating and splitting stereo pairs* (and adding or removing a sub or surrounds), which Roomtone leaves to the Sonos app today. The speakers appear to have local commands for it (`CreateStereoPair` and `SeparateStereoPair` in `DeviceProperties`; **they are in a real speaker's service description, checked read-only 2026-11-22**, though not yet tried), but it needs two identical, pairable speakers of our own to try on, since a half-made pair can leave a speaker hidden or on the wrong channel until the Sonos app fixes it. Pairs that already exist are shown as one room (hidden members skipped); that is built in but hasn't been tried on a real pair. Raised by a tester, 2026-11-20. The wider speaker-setup idea this belongs to is item 22 (with sound settings in 24 and layouts in scenes in 23).
12. **Accessibility follow-ups**: names, roles, focus, announcements and keyboard menus are in and VoiceOver on macOS works; sliders say their value in words, Ctrl/Cmd+1 to 9 picks a room, and a *High contrast* setting exists (all added in 0.9.3, checked by tests and pictures, not yet with a screen reader). Still to do: try Narrator, NVDA and Orca (and VoiceOver again), follow the computer's own high-contrast or increased-contrast setting automatically, raise the usual palettes' faint text (about 3:1) if testers find it hard to read, and check text size changes.
13. **Recorded replies from real speakers** as test cases (with names and addresses removed), to complement the hand-written samples in the unit tests.
14. **Scene follow-ups**: a *Do it* shortcut from the tray, and scheduling a scene (an alarm that does a scene; the speakers' own alarms can't, so it would only work while Roomtone is running). (Shuffle and *Save what's playing as a scene* shipped after 0.9.6, the two things the Sonos app's presets had that scenes lacked; cloud sync and a phone app were left out on purpose. Sound settings per room and scenes in backups shipped after 0.7.0.)
15. **Tidy up the interface (a theme, not one feature)** *(started in 0.9.0: Settings is now seven tabs, with all speaker settings together and Music Services moved in (podcasts and Internet Archive live in Music Library), and Line-In & TV has one row per speaker; next candidates: the long About card, Home, Now Playing and the sidebar)*: so far the focus has been on adding features, so pages have grown by accretion. Aim for one clear, coherent design: consistent spacing, headings, buttons and empty states; fewer things on screen at once; the common actions (play, volume, rooms, queue) always easy to reach; settings sorted by how often they're needed. Take inspiration from other music players and streaming apps (how they lay out Now Playing, queues, search and rooms or devices) without copying anyone's artwork or code. This needs people with UI/UX skill and feedback from real users, not only the maintainers: ask what they'd like and where they get lost (an issue or discussion asking for it, and a few short sessions watching someone use the app for the first time), then sketch before building. Do it in small pull requests, one page at a time, each with demo screenshots before and after, in English and one longer language, light and dark; keep the screen-reader names, focus rings and keyboard paths intact.
16. **Other kinds of speakers (exploration first)**: could and should Roomtone also control speakers that aren't Sonos? Look at AirPlay (receivers such as HomePods, Apple TVs and many speakers), Google Cast (Chromecast and Cast-enabled speakers), and other network streaming speakers (for example DLNA/UPnP renderers, which Sonos itself speaks, and the vendors' own multi-room systems). For each, find out: how a controller finds and talks to the device (and whether it's documented or reverse-engineered, and the licence of any library we'd use), what it can do (play a URL, volume, grouping, queue, status, events), how it would fit our model of rooms, groups and Now Playing, what music sources would work (our own library and radio could be sent to it; streaming services mostly can't), what the legal and trademark position is (names and logos, protocol terms), and what it would cost in testing, since we'd need real devices. The first step is a short written report, with a recommendation, and perhaps a tiny read-only prototype that only finds devices and lists them; no changes to how Sonos control works until the report is agreed.
17. **A console launcher for Windows scripts**: because the Windows program has no console, scripts can't wait for it or read its exit code without `start /wait`. A tiny console program named `roomtone.com` next to `roomtone.exe` (Windows picks `.com` first when typing `roomtone`) could run the real program and pass its output and exit code back. Only worth it if people script the command line on Windows.
18. **MCP protocol 2026-07-28 (the current revision)**: no `initialize` handshake or sessions (every request carries its version and capabilities), a `server/discover` call, `subscriptions/listen` instead of `resources/subscribe` and our event stream, a required `resultType` on results, cache hints (`ttlMs`, `cacheScope`) on lists, `Mcp-Method` headers, `ping` removed, and "resource not found" becoming -32602. 29. **Keep favorites and playlists in step between systems (recommended approach, 2026-11-25)**: a home with an S1 and an S2 system has two separate sets of favorites, playlists and alarms, and the Sonos apps don't share them. Roomtone already holds both systems and has the pieces: it reads a system's lists, compares by title and address (the restore's duplicate check) and adds without deleting. Build it in three small steps, each safe on its own. **(1) *Copy to another system*** on Favorites and Playlists (and a *Copy to…* in the room's ⋯ menu for alarms): pick items, pick a target system, see a preview of what would be added and what the target already has, then confirm; adds only. It reuses the backup/restore code with a live system as the source instead of a file. **(2) *Sync these systems***: choose two or more systems and which lists (favorites, playlists, alarms by room name, scenes); Roomtone shows, per system, what it is missing from the others, and adds it after a confirmation. It is a union: it never changes or removes anything, so deleting an item in one system has to be done in each (say so in the window). **(3) Optional *Keep in step* switch** (off by default) that offers a sync when Roomtone starts or a list changes, still only after the person confirms, never silently writing to speakers. Things to settle first: streaming-service favorites carry the service's account number (`sn`) and only play on a system where that service is connected, so skip or flag them when the target lacks it (this is also item 2's open problem); radio stations, library items and playlists of local songs copy cleanly; S1 and S2 saved playlists use the same calls, but check on real speakers; alarms need matching room names, so offer a room mapping (Kitchen → Kitchen) rather than guessing; a one-way *copy* is simpler to explain than a two-way sync, so ship (1) first. Settings that are Roomtone's own (stations, podcasts, saved groups, scenes) are already shared by both systems and need nothing.
